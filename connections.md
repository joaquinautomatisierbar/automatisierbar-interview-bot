# Connections

Registry of every system the AIOS can reach, mapped to the 7 universal data domains. Update whenever a new tool gets wired (or unwired). The `/audit` skill reads this file to score the **Connections** axis.

**Mechanism legend:** `mcp` (MCP server), `n8n` (native node inside an n8n workflow), `script` (Python/Bash in `tools/` hitting an API), `hook` (shell script in `.claude/hooks/`), `key+ref` (`.env` key + `references/<tool>-api.md` guide), `not yet connected`.

**RW** = Read+Write (can mutate). **R** = Read-only.

## Domain-coverage gaps (as of 2026-05-02)

- **Domain 1 (Revenue / Financials)** — nothing wired. We don't currently route Stripe / accounting / invoice data through the AIOS. Lowest priority until revenue volume justifies it.
- **Domain 6 (Meeting intelligence)** — nothing wired. Cold-call audio is captured manually into Drive (Workflow C). No Granola / Otter / Fireflies integration. If we start running internal team meetings or client calls beyond cold-calls, this becomes worth wiring.
- **Domain 3 (Calendar)** — read-only. Can't create / update events. If a use case lands (e.g. "AIOS books follow-up calls with hot leads"), we'd need Google Calendar API via `n8n` or a script — the MCP server doesn't expose write tools.
- **Domain 4 (Gmail)** — read-only via MCP. Outbound email goes through n8n SMTP only. If we want AIOS-driven send-from-inbox (replies in thread), wire Gmail API via n8n Gmail node or Python script.
